# QRCT 失败复盘：风险系数监督接口为何没有形成充分创新

## 1. 这项创新原本想解决什么问题

QRCT（Query-Risk-Coefficient Transfer，查询风险系数迁移）面向一个具体的概率预测场景：

- 预测训练阶段未见过的新充电站；
- 输入只有起报时刻之前最近一周的历史状态；
- 历史数据存在缺失；
- 预测目标是有明确容量上限的整数 busy 数，而不是连续电量；
- 输出必须是容量支持集内的完整离散概率分布。

核心困难不是“能不能训练一个更大的预测器”，而是新站点只有很短的历史，基础预测器在当前站点、当前时段和当前预测跨度上的失配可能与源站点不同。QRCT 希望利用新站点短历史中已经发生的预测误差，推断当前查询应该怎样修正基础概率分布。

## 2. QRCT 的核心方法是什么

QRCT 先训练并冻结一个容量有界的 CNP-Beta-Binomial 基础模型。对于当前查询，基础模型输出一个有限支持集上的 PMF：

$$
p_{q0}(y),\qquad y=0,1,\ldots,C.
$$

然后对基础 CDF 使用四个固定 Beta-CDF 变换，得到四个非恒等候选分布。恒等分布和四个变换共同构成五分量字典：

$$
G_0(u)=u,
$$

$$
(\xi,\zeta)\in
\{(0.5,0.5),(2,2),(0.5,2),(2,0.5)\}.
$$

每个候选分布与基础分布的 CDF 差异形成一个四维风险系数。离散 CRPS 的差异可以写成：

$$
S(F_w,y)-S(F_0,y)=w^\top A_qw-2b_q(y)^\top w.
$$

其中：

- \(A_q\) 是当前查询可直接计算的候选分布 Gram 矩阵；
- \(b_q(y)\) 是只有未来标签出现后才能得到的风险系数；
- \(w\) 是四个非恒等分量的权重，剩余权重留给恒等分布。

QRCT 的中心主张是：

1. 用因果回放得到源站点短历史中的风险证据；
2. 用源站点监督数据学习当前查询风险系数的条件均值 \(\widehat b_q\)；
3. 在当前查询时重新计算准确的 \(A_q\)；
4. 解一个四维受约束二次问题，得到最终混合分布。

因此，QRCT 并没有提出新的 CRPS、凸优化、Beta-Binomial 或 CDF 变换理论。它声称的增量是“监督预测未知风险线性项，同时直接使用当前查询已知的完整二次风险结构”。

## 3. 预先设计的强对照

为了避免把普通校准或损失函数变化误认为创新，实验预先安排了以下对照：

| 方法 | 含义 |
|---|---|
| M0 / C0 恒等基座 | 冻结基础 CNP-Beta-Binomial，不做适配 |
| C1 等权混合 | 五个固定分量直接等权混合 |
| C2 局部 CRPS stacking | 使用相同回放证据和候选字典，直接优化历史 CRPS；带宽和正则在验证集选择 |
| M5 DIET-CRPS | 使用查询条件先验、历史似然证据和查询相关权重，只把源查询训练目标改为 CRPS |
| M6 QRCT | 风险系数监督 + 当前查询 \(A_q\) 的二次优化，QRCT 首选方案 |
| M7 直接条件门控 | 使用与 M6 相同的回放证据、查询条件、编码器宽度和注意力结构，直接预测五个混合权重并以 CRPS 训练 |
| C3 历史矩阵替代 | 复用 M6 风险系数预测，但把当前 \(A_q\) 替换为注意力加权的历史 \(A_i\) |

M7 是最重要的同信息竞争解释：如果 M7 与 M6 一样好，QRCT 的风险系数接口就可能只是普通条件门控的另一种参数化。

### 3.1 数据、划分与证据边界

实验使用公开 UrbanEV 数据集的固定版本（Dryad version 423269）。原始观测覆盖 2022 年 9 月至 2023 年 2 月，共 1,682 个站点 ID。为防止同一位置的多个 ID 泄漏，站点按精确坐标组成 1,543 个组，再以组为单位划分角色。

本轮核心归因只使用：

- 早期基础训练站点训练和选择冻结的 CNP-Beta-Binomial；
- 2022 年 11 月的独立源站点训练适配器；
- 2022 年 12 月的独立方法验证站点选择检查点和超参数；
- 每日 05:55、11:55、17:55、23:55 起报，预测未来 1–6 小时；
- 最近 168 个小时槽作为当前上下文，至少 24 个有效观测才进入 few-shot 主评价；
- 每个查询最多 72 条因果回放证据，所有证据标签都在当前起报时刻之前已经发生。

核心比较覆盖 120,296 条有效查询、215 个站点、209 个坐标组和 24 个验证日。只完成了第一个冻结种子。独立校准角色和最终测试角色始终未打开，因此本文记录的是方法验证结论，不是最终测试结论，也不是三种子重复性结论。

## 4. 首种子方法验证结果

所有方法在相同的验证查询集合上比较。主指标是站点宏平均原始离散 CRPS，数值越低越好。

| 方法 | 验证 dCRPS |
|---|---:|
| C0 恒等基座 | 1.063649 |
| C1 等权混合 | 1.097157 |
| C2 局部 CRPS stacking | 0.888250 |
| M5 DIET-CRPS | 0.895729 |
| M6 QRCT | **0.872356** |
| M7 直接条件门控 | 1.049785 |

M6 的点估计最好，但这不足以自动证明创新成立。预注册的关键对照差值及 1,000 次同址组与共享七日循环块配对重采样结果如下：

| 配对差值 | 点估计 | 95% 区间 | 解释 |
|---|---:|---:|---|
| M6 − M7 | -0.177429 | [-0.232044, -0.130239] | QRCT 明显优于同信息直接门控 |
| M6 − M5 | -0.023373 | [-0.055425, 0.001407] | 区间跨 0，不能确认优于 DIET-CRPS |
| M6 − C2 | -0.015894 | [-0.060442, 0.027009] | 区间跨 0，不能确认优于局部 stacking |
| M6 − C3 | -0.000021 | [-0.000915, 0.001174] | 当前矩阵相对历史矩阵没有可确认增量 |

站点级结果也显示：

- M6 相对 M7 在 174/215 个站改善；
- M6 相对局部 stacking 的点估计更好，但配对区间跨 0；
- C3 与 M6 几乎相同，说明使用当前 \(A_q\) 并未带来可辨认的额外收益；
- M5 在 123/215 个站优于 M6，但少数站点的较大损失使其宏平均略差。

## 5. 失败的准确含义

QRCT 不是“完全没有效果”。更准确的结论是：

1. 风险系数监督接口明显优于同信息直接门控；
2. QRCT 在首种子验证集上的点估计优于局部 stacking 和 DIET-CRPS；
3. 但相对这两个强对照的 95% 配对区间都跨 0；
4. 当前查询完整矩阵 \(A_q\) 相对历史矩阵 \(A_i\) 的独立作用接近 0；
5. 因此不能把“风险系数监督 + 当前完整二次风险”整体写成已经被充分验证的新概率预测机制；
6. 不能启动更多种子、校准集或最终测试集来寻找有利结果，因为核心归因门已经没有通过。

这是一项“部分机制有效、中心创新主张证据不足”的失败，而不是基础模型或代码完全失败。

## 6. 失败的主要原因

### 6.1 把可解释的代数分工误认为可验证的性能增量

QRCT 把风险差异分解成“未知线性项 \(b_q\) + 当前已知二次项 \(A_q\)”在数学上是正确的。但数学分解不等于任务上的独立收益。

实验中 C3 几乎复现 M6：

- M6：0.872356；
- C3：0.872377；
- 差值约 0.000021，配对区间跨 0。

这说明当前 \(A_q\) 的精确查询结构并没有成为主要性能来源。主要收益更可能来自风险系数监督本身，或者来自由监督网络产生的稳定权重，而不是“当前矩阵必须直接进入优化”这一完整叙事。

应避免的错误：

> 看到一个漂亮的平方展开，就直接把展开中的每个部分都命名为创新贡献。

正确做法是逐段验证：表示差异是否改变权重，权重是否改变预测分布，预测分布是否改变最终评分。

### 6.2 对强局部 stacking 基线估计不足

局部 stacking 使用了：

- 与 QRCT 相同的冻结基础预测器；
- 相同的因果回放证据；
- 相同的五个固定候选分布；
- 相同的验证集调参机会；
- 只依赖起报时间、星期、预测跨度和滞后的局部相似度。

它的验证 dCRPS 为 0.888250，已经非常接近 M6 的 0.872356。M6 的优势只有 0.015894，而且配对 95% 区间跨 0。

这表明：在当前数据量、候选字典和短历史协议下，简单的查询局部加权已经能捕捉大部分可迁移信号。QRCT 没有证明自己的监督接口能够稳定超过这种强基线。

应避免的错误：

- 只比较弱基座，不比较同信息的局部校准；
- 把“神经网络更复杂”误当作“信息接口更有效”；
- 只报告点估计，不报告配对不确定性。

### 6.3 直接门控对照没有被正确解释为“失败的替代解释”

M7 结果很差，验证 dCRPS 为 1.049785。它明显弱于 M6，但这只能支持一个有限结论：在当前训练预算、参数化和优化轨迹下，直接预测五分量权重不如监督预测风险系数。

它不能证明：

- 风险系数接口在所有门控网络中都更好；
- M7 的训练目标、输出约束和 M6 完全等价；
- QRCT 已经超越所有条件 stacking 方法。

应避免的错误：

> 只要一个强对照失败，就把它写成创新已经被证明。

强对照失败只能排除一个替代解释，不能替代对其他强对照和不确定性的检验。

### 6.4 有限五分量字典限制了可归因性

五个候选分布全部来自基础 CDF 的固定 Beta-CDF 变换。这个设计有优点：

- 支持集合法；
- PMF 非负且归一化；
- 容量变化时仍可复用；
- 参数少，便于控制实验。

但它也限制了可表达的分布形状。多个不同的权重组合可能产生非常相近的最终 PMF，导致：

- 权重变化不一定带来明显分布变化；
- \(A_q\) 和 \(A_i\) 的差异不一定能转化为评分差异；
- 监督目标的改善不一定能传递到最终 CRPS。

应避免的错误：

> 看到中间权重发生变化，就默认最终分布和任务评分一定发生同方向变化。

必须检查从系数、权重、PMF 到评分的完整链条。

### 6.5 训练目标和主评价目标没有完全一致

M6 训练的是归一化风险系数均方误差：

$$
\|\widehat b_q-b_q(y_q)\|_2^2.
$$

主评价却是原始连接器计数尺度上的站点宏平均 dCRPS。两者存在合理的结构关系，但不是同一个优化目标：

- 风险系数误差是归一化的；
- 主指标按站点和时域宏平均；
- 站点容量、缺失率和历史数量不同；
- 小的系数误差在高容量站可能放大为更大的原始 CRPS 差异。

M6 的风险系数 MSE 相对源站点按时域均值基线降低约 36.4%，但这并没有对应一个对局部 stacking 稳定显著的 dCRPS 改善。

应避免的错误：

> 只要代理损失明显改善，就认为主任务指标一定显著改善。

代理损失必须同时验证与主指标的相关性、单调性和跨站稳定性。

### 6.6 只完成一个种子的核心实验，证据强度不足

首种子结果足以触发停止规则，但不能支持普适性结论。当前结果只能说明：在一个固定种子和一个方法验证期内，QRCT 的点估计较好，但相对强基线的配对不确定性仍然很大。

停止其他种子是正确的研究决策，因为继续增加种子、直到结果显著，会把开发过程变成结果筛选。以后如果重新提出类似方法，应在揭盲前明确：

- 至少需要多少个独立种子；
- 哪个比较是主要检验；
- 何时停止扩展；
- 是否允许重新调参。

## 7. 工程实现中出现的问题

这些问题没有直接制造 QRCT 的科学失败，但暴露了需要提前防范的工程风险。

### 7.1 CDF 尾部浮点误差导致 NaN

在固定 Beta-CDF 变换中，浮点累积可能使 CDF 略微超过 1。随后 `betainc` 在非法输入上产生 NaN，污染了少量查询和回放记录。

处理方式：

- 对基础 CDF 截断到 [0,1]；
- 强制单调累积；
- 强制最后一个 CDF 值为 1；
- 写出缓存前做全量有限性断言；
- 独立验证缓存中的每一列。

以后应在最初的数学单测中加入 0、1、近 0、近 1 和最大容量边界，不要等到大缓存生成后才发现尾部问题。

### 7.2 Windows 数值后端的批量线性代数中止

四维 QP 最初使用批量 `numpy.linalg.solve`，在当前 Windows 数值后端中出现进程级中止，而不是普通 Python 异常。随后改用小维度显式 Cholesky 求解，绕过批量 LAPACK 调用。

以后应在目标运行环境中做最小数值后端冒烟：

- 单矩阵求解；
- 批量矩阵求解；
- 奇异矩阵和正则化矩阵；
- 多进程或 GPU 初始化后的调用。

### 7.3 调参网格边界问题

局部 stacking 的最优带宽一开始落在候选网格最小值 0.25。若直接冻结，会留下“最优点被网格截断”的疑问。后来只在验证集内向下扩展到 0.0625 和 0.125，最优仍为 0.25。

以后应在实验开始前写明：

- 候选网格；
- 边界扩展规则；
- 最大扩展次数；
- 扩展后是否重新冻结。

不能看到验证集最优点后无限向有利方向扩网格。

### 7.4 非标准 JSON 的 NaN

Pandas 将“无带宽”写成 NaN，导致第一次结果报告不是严格标准 JSON。数值结果没有改变，但会影响跨工具读取和长期归档。

以后写报告时必须：

- 使用 `allow_nan=False`；
- 用 `null` 表示不存在的数值；
- 在写文件后立即用独立 JSON 解析器读取；
- 把报告格式验证作为实验验收的一部分。

## 8. 哪些内容仍然值得保留

QRCT 失败不意味着所有设计都应该丢弃。以下部分具有可复用价值，但不能自动称为已证实的新颖算法：

1. 先冻结基础概率模型，再用因果回放模拟部署时可获得的历史误差；
2. 将历史误差放在概率坐标上，而不是只使用点预测残差；
3. 让证据选择依赖当前查询的时段、星期、预测跨度和滞后；
4. 使用容量合法的有限 PMF 字典，避免输出超出物理支持；
5. 用同信息直接门控、DIET-CRPS、局部 stacking 和矩阵替代做归因；
6. 同时报点估计、配对区间、站点胜负和数据暴露；
7. 在核心归因门未通过时停止扩展，而不是继续添加模块挽救主张。

最可靠的保留表述是：

> QRCT 的风险系数监督接口在首种子验证中明显优于同信息直接条件门控；但相对局部 CRPS stacking 和 DIET-CRPS 的独立优势尚未建立，当前查询矩阵相对历史矩阵也没有显示出可确认的增量。因此，QRCT 应作为一次有价值的概率误差迁移实验和失败复盘保存，而不是作为已经证实的新概率模型发表。

## 9. 以后做创新时必须遵守的流程

### 9.1 先定义可证伪的失败机制

不要从“泛化不足”“概率预测不准”“缺少自适应能力”开始。应写成可测量的陈述，例如：

> 在固定查询条件下，基础模型的某类概率误差会由短历史中的某种可观测信息稳定预示，而简单局部校准无法解释全部增量。

### 9.2 先列出最强简单解释

至少包括：

- 更多训练数据；
- 全局校准；
- 局部校准；
- 等权或近期加权；
- 同信息直接门控；
- 仅换损失函数；
- 历史统计量替代当前结构。

如果新方法不能稳定超过这些对照，不要把它包装成中心创新。

### 9.3 将每个新增部件单独拆开

对于一个组合方法，至少需要回答：

1. 新表示是否改变了中间目标；
2. 中间目标是否改变了权重；
3. 权重是否改变了 PMF；
4. PMF 是否改善了主评分；
5. 改善是否超过训练波动和强基线不确定性。

如果只能证明第 1 步，不能把第 5 步写成已证实。

### 9.4 预先冻结调参、统计和停止规则

实验前应冻结：

- 数据版本和时间划分；
- 允许读取的信息；
- 候选字典；
- 学习率、更新上限和早停规则；
- 调参网格和边界扩展规则；
- 主要对照；
- 配对重采样单位；
- 何时停止后续种子和最终测试。

### 9.5 不把“不显著”改写成“等价”

配对区间跨 0 只表示当前证据不足以确认方向，不表示两个方法已被证明等价。应报告：

- 点估计；
- 95% 区间；
- 改善和恶化的站点数量；
- 评价集合大小；
- 训练种子数量；
- 仍未解决的替代解释。

### 9.6 测试集揭盲后不再开发

最终测试集只能用于冻结方案的最后评价。不能在看到测试结果后：

- 换候选方法；
- 修改主指标；
- 扩大种子数量；
- 重新选择子群；
- 追加校准或后处理；
- 删除表现不好的压力期。

## 10. 最终停止结论

QRCT 的中心创新主张停止在方法验证阶段：

- 保留风险系数监督、因果回放和查询条件化证据迁移的经验价值；
- 删除“当前完整二次风险结构带来独立性能增量”的强主张；
- 不把 QRCT 写成已经击败局部 stacking 或 DIET 的新概率模型；
- 不继续启动其他种子或最终测试来寻找有利证据；
- 若未来重新做创新，应从新的、可测量的失败机制出发，并把局部 stacking 和直接门控作为一开始就存在的强基线。

最需要记住的一句话是：

> 一个方法可以在点估计上最好，同时仍然没有足够证据证明它的核心创新；真正要证明的不是“整体代码有效”，而是“新增的信息接口相对最强替代解释具有稳定、可归因、可重复的任务增量”。
